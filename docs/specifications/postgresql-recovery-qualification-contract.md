# PostgreSQL recovery qualification report contract

**Status:** `v1alpha1` executable local recovery evidence  
**Machine contract:** `contracts/schemas/postgresql-recovery-qualification-report.schema.json`

`PostgreSQLRecoveryQualificationReport` is source-bound evidence from one
disposable, complete-schema logical backup and isolated restore. The report is
generated by `make test-backup-restore`; it is not served by the control-plane
API and contains no database URL, credential, host name, tenant identifier, raw
resource, evidence, investigation, action, or plugin document.

The only accepted profile is `quiesced-logical-restore-v1`. It seeds one
representative workflow through the ordinary application and PostgreSQL
boundaries, records a canonical manifest of every `iip` table and identity
sequence, takes a custom-format `pg_dump`, proves the source remained unchanged,
restores into a distinct database, compares the complete manifest, and runs the
tenant-scoped projection verifier. Per-table row counts and hashes make schema
coverage auditable without copying stored values into the report. Sequence
state is represented only by a count and aggregate digest.

Checks are closed and ordered. `qualified` means representative state existed,
the dump covered the complete schema, the quiesced source stayed stable, the
restore was isolated, row and sequence state matched, projections agreed with
accepted observations, and the two declared local timing guardrails passed.
The verifier derives those results from measurements and rejects missing,
invented, reordered, or contradictory checks. A timing miss produces a
schema-valid `failed` report and a failing command so the measured failure can
still be retained.

`metadata.sourceRevision` and `metadata.sourceDirty` identify the exact checkout
that executed the profile. Dirty-source reports are useful during development
but are not release evidence. Promotion tooling uses `--require-clean` and also
requires the report revision and application version to equal the current clean
checkout.

This profile does not measure continuous writes, WAL retention, replica lag,
automatic failover, point-in-time selection, retained-storage durability,
encryption, immutability, regional recovery, representative data volume, or a
customer recovery objective. Those require separately executable profiles
against the chosen production PostgreSQL service; they cannot be inferred from
this report.
