# Investigation dispatch capacity report contract

**Status:** `v1alpha1`  
**Machine contract:** `contracts/schemas/investigation-capacity-report.schema.json`

This report is executable, source-bound evidence that the durable PostgreSQL investigation queue preserves its accepted capacity and isolation semantics under a declared large-tenant and overload profile. It is generated by `make test-capacity`, not by the control-plane API, and contains aggregate measurements only.

The profile declares tenant and job counts, parallel clients, outstanding-job and live-lease caps, and deliberately generous local timing objectives. Measurements cover bulk admission, an over-cap burst, idempotent retry while full, a separate tenant during overload, one first-pass claim per tenant, same-tenant second-claim denial, terminalization, and replacement admission. Checks are closed and ordered so automation can compare reports without interpreting free text.

`certified` means every semantic and timing check passed for the exact source revision, database version, migration, host platform, and declared profile in the report. It is not a universal throughput promise or a production sizing result. A dirty-source report is useful during development but is not release evidence. Customer qualification must repeat the profile on the intended database class, network, worker replica count, provider latency distribution, and tenant/job scale.

The report never contains tenant identifiers, request bodies, questions, evidence, provider responses, database credentials, host names, or connection strings. Failure checks expose only stable error codes.
