# AI FinOps runtime compatibility contract

**Status:** Accepted local evidence contract  
**API version:** `iip.dev/v1alpha1`

`AiFinopsRuntimeCompatibilityReport` is source-bound evidence for the
repository's complete local AI FinOps reference flow. It is generated by the
Docker gate only after metadata-only Bedrock- and OpenAI-shaped spans traverse
the customer-replaceable Collector boundary, isolated trace receiver,
PostgreSQL ledger, attribution and cost workers, bounded OTLP aggregate export,
Prometheus, and the provisioned Grafana dashboard.

The report retains release and runtime versions, fixed aggregate counts,
ordered checks, and explicit limitations. It omits provider model IDs, service
names, tenant identifiers, channel credentials, trace/span/request IDs, token
quantities, catalog rates, monetary amounts, source locators, and content. Its
content-derived `afc_` identity covers metadata other than the ID plus the
complete specification.

The profile proves all of the following in one disposable topology:

- two provider shapes use the same provider-neutral ledger and dashboard;
- accepted spans are durably persisted before downstream calculation;
- content-bearing spans are rejected and exact replay is idempotent;
- complete and explicitly unpriced cost coverage remain distinct;
- one partial Bedrock-shaped usage fact is priced only through exact output
  rate equivalence and carries the aggregate-output warning;
- protected attribution, three deterministic finding types, bounded OTLP
  aggregate export, and the dashboard are executable together.

`compatible` means the exact local gate passed. It is not customer or provider
certification. The mandatory limitations preserve that the spans and prices
are fixtures, the runtime is one Docker host, and customer Collector/PKI,
network, live provider, private pricing, invoice, sustained-load, regional-HA,
and backend-lifecycle claims remain separate.

Use `make test-ai-finops PYTHON=.venv/bin/python` to generate the report and
`make verify-ai-finops-runtime-report PYTHON=.venv/bin/python` to require a
schema-valid, identity-valid report whose clean revision and application
version match the current checkout.
