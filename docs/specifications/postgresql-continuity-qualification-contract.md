# PostgreSQL continuity qualification report contract

**Status:** `v1alpha1` executable local physical-continuity evidence  
**Machine contract:** `contracts/schemas/postgresql-continuity-qualification-report.schema.json`

`PostgreSQLContinuityQualificationReport` is source-bound evidence from one
disposable physical replication, manual promotion, WAL archive, and named-target
recovery experiment. It is generated by `make test-postgres-continuity`, is not
served by the control-plane API, and grants no database or cluster authority.

The report contains no credential, database URL, host/container name, tenant or
actor identifier, resource UID, external resource ID, raw row, or stored
document. It records only source/environment identity, aggregate fixture and
backup measurements, PostgreSQL LSNs and timelines, timings, row/sequence
digests, table counts/digests, projection-verifier output, the recovery boundary,
and closed checks.

## Accepted profile

`physical-streaming-pitr-v1` performs the following ordered experiment:

1. Start digest-pinned PostgreSQL with streaming replication and WAL archiving,
   migrate it, and seed the representative platform workflow.
2. Take independent PITR and standby physical copies with `pg_basebackup` and
   streamed WAL.
3. Start the asynchronous standby and verify it is in recovery.
4. Commit a before-target marker, create `iip_pitr_target`, commit an
   after-target marker, and force the containing WAL segments into the archive.
5. Wait until the standby has replayed the primary flush LSN with zero measured
   byte lag and compare every `iip` table.
6. Stop the primary, manually promote the standby, verify its new timeline,
   complete table state, sequence floor, and serving projections.
7. Recover the independent copy from archived WAL to the named point, then prove
   exact target-row state and the marker boundary before verifying projections.

Two sequence digests can legitimately differ. PostgreSQL pre-logs sequence
allocations so a standby or recovered copy may advance to a higher safe value.
The `sequenceFloorSatisfied` condition requires equal sequence membership and
configuration and rejects a recovered last value that moves backward for the
declared increment direction. This preserves identifier safety while permitting
expected gaps after recovery.

## Closed result

The twenty checks are ordered and exhaustive: representative state, two
physical base backups, streaming recovery, zero-lag cutover, standby row and
sequence safety, primary stop, standby promotion, promoted row/sequence/
projection integrity, WAL archive, named restore target, PITR boundary and
row/sequence/projection integrity, then catch-up, failover-ready, and PITR-ready
guardrails.

`spec.status` is derived from those checks. A timing miss yields a schema-valid
`failed` report and a non-zero command status. Structural integrity failures
abort without publishing a misleading completed report. The semantic verifier
recomputes row digests and totals, check outcomes, report identity, pinned image,
and clean-current-source binding.

`metadata.sourceRevision` and `metadata.sourceDirty` bind the observation to the
checkout. Promotion verification additionally requires the application version
and latest migration to match the current clean source.

The profile is a single-host Docker regression gate. It does not claim automatic
failover, fencing, service discovery, customer storage durability, archive
retention, encryption, regional disaster recovery, production load, or a
customer RPO/RTO.
